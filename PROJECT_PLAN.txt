React (frontend) + Node.js/Express (backend) + PostgreSQL (database)
==============================================================================

HOW TO USE THIS FILE
--------------------
1. Unzip expense-tracker.zip. All files exist but are EMPTY.
2. Work phase by phase, in order. Do not skip ahead.
3. Each phase has: Goal, Files to fill, Tasks, and a "Done when" checklist.
4. Finish and test a phase before starting the next one.
5. When asking for code, tell me "Phase X, Step Y" and I will give you the
   code for exactly those files.

TECH STACK
----------
Frontend : React 18 + Vite, React Router, TanStack Query (server data),
           Redux Toolkit (auth/UI state), Tailwind CSS, React Hook Form + Zod,
           Recharts (charts), Axios, i18next (English + Arabic/RTL ready)
Backend  : Node.js 20, Express, pg (node-postgres), JWT (access + refresh),
           bcrypt, Zod/Joi validation, Helmet, CORS, express-rate-limit,
           Winston (logging), Multer (uploads), node-cron (jobs),
           Nodemailer (emails), pdfkit + exceljs (exports), Swagger docs
Database : PostgreSQL 15+ with plain SQL migrations
DevOps   : Docker + docker-compose, GitHub Actions CI, ESLint + Prettier
Testing  : Jest + Supertest (backend), Vitest + Testing Library (frontend)

PROJECT STRUCTURE (OVERVIEW)
==============================================================================
expense-tracker/
  backend/
    src/
      config/          env, db pool, logger, cors, swagger
      routes/          URL -> controller mapping
      controllers/     read request, call service, send response
      services/        business logic
      repositories/    SQL queries only (database access)
      middlewares/     auth, validation, errors, rate limit, upload
      validators/      request schemas
      utils/           helpers (ApiError, jwt, hash, pagination ...)
      jobs/            scheduled tasks (recurring, alerts, weekly summary)
      templates/       email HTML templates
    database/          migrations, seeds, runner scripts
    tests/             unit + integration
    docs/openapi.yaml  API documentation
  frontend/
    src/
      app/             store, query client, providers
      routes/          router, protected/public routes
      layouts/         main layout, auth layout, sidebar, topbar, bottom nav
      pages/           one folder per screen
      features/        feature logic: hooks, forms, tables, charts
      components/      reusable UI (ui/) and shared (common/)
      api/             axios client + one file per resource
      hooks/ utils/ styles/ i18n/ assets/ tests/
  docs/                architecture, schema, API, deployment, contributing
  .github/workflows/   CI and deploy
  docker-compose.yml   app + postgres

Architecture rule (backend):  Route -> Controller -> Service -> Repository -> DB
Architecture rule (frontend): Page -> Feature components/hooks -> API file

PHASE 1 - DATABASE DESIGN
==============================================================================
Goal: Full database schema created by migrations, with default data.

Files to fill:
 - backend/database/migrations/001 ... 010 (.sql)

 - backend/database/seeds/002_demo_data.sql

 - docs/DATABASE_SCHEMA.md

Tables:
 users                 id (uuid), name, email (unique), password_hash, avatar_url,
                       currency, language, theme, role, email_verified,
                       created_at, updated_at
 refresh_tokens        id, user_id, token_hash, expires_at, revoked, created_at
 accounts              id, user_id, name, type, balance, currency, color,
                       is_archived, created_at
 categories            id, user_id (null = default), name, type (income/expense),
                       icon, color, is_default
 expenses              id, user_id, account_id, category_id, amount, date, note,
                       payment_method, tags[], receipt_url, recurring_id,
                       created_at, updated_at
 incomes               id, user_id, account_id, category_id, amount, date, source,
                       note, recurring_id, created_at, updated_at
 budgets               id, user_id, category_id (null = overall), amount, month,
                       year, alert_threshold, created_at
 recurring_transactions id, user_id, type, amount, account_id, category_id,
                       frequency, start_date, end_date, next_run_date, is_active
 notifications         id, user_id, type, title, message, is_read, created_at

Tasks:
 1.1 Draw the ER diagram (relations: user has many accounts, categories ...).
 1.2 Write each migration (CREATE TABLE, constraints, foreign keys).
 1.3 Write 010 indexes (user_id, date, category_id on expenses/incomes).
 1.4 Build migrate.js to run migrations in order and track them.
 1.5 Seed default categories (Food, Transport, Rent, Bills, Shopping, Health,
     Entertainment, Education, Salary, Freelance, Gifts ...).
 1.6 Document the schema in docs/DATABASE_SCHEMA.md.

Done when:
 [ ] "npm run migrate" creates all tables from scratch
 [ ] "npm run seed" fills default categories
 [ ] Foreign keys and indexes are verified in psql/pgAdmin

 4.5 Budgets      (CRUD per month, spent vs limit calculation)
 4.6 Recurring    (CRUD, pause/resume, next_run_date calculation)

Rules:
 - Every query is filtered by the logged-in user_id (never trust client ids).
 - Creating/updating/deleting an expense or income updates the account balance
   inside a database TRANSACTION.
 - Money is stored as NUMERIC(12,2), never float.
